# 信息 APP

桌面新增「信息」，经典桌面与自由桌面都能打开。数据保存在当前浏览器，不使用真实运营商短信或苹果 iMessage 网络。

## 开始使用

1. 打开「信息 → 右上角 … → 信息设置」，开启信息并保存。号码为空时自动生成固定的 11 位虚拟号码。
2. 「通讯录」中可以向已有角色询问号码，由角色结合人设与关系决定接受、拒绝或暂缓；也可以在 QQ 聊天中自然地交换号码。
3. 已获得的号码可在「新信息」中输入。未获知身份的来信显示号码，手动保存后按备注显示。
4. 「发送」只保存自己的信息，不调用模型。「API 回复」一次处理尚未回复的多条消息。自动回复默认关闭。
5. 照片可随信息发送，API 回复时交给当前所选模型读取；需要该模型支持图片输入。引用、气泡回应与时间会一起提供上下文。

## 自定义提示词与 API

全局设置和联系人详情中的独立设置均可编辑短信提示词。修改联系人参数会自动取消「沿用全局设置」，保存后生效。

- 补充模式保留默认短信风格，附加个人偏好。
- 替换模式使用自己的短信风格，人物身份和 JSON 收发协议仍由程序维护。
- 可使用 `{{角色名}}`、`{{用户}}`、`{{号码}}`、`{{我的号码}}`、`{{时间}}`。
- 另外支持陌生人相遇偏好、记忆总结要求和本次回复要求。
- API 可沿用角色配置、全局配置，或使用信息独立配置。选择独立配置后，地址、密钥和模型必须齐全，不借用其他配置的密钥。
- 查看默认提示词、恢复默认风格不会调用 API。

## 上下文与长期记忆

短期短信上下文支持 1～200 条，跨渠道近期参考支持 0～100 条；完整记录仍保留。

互通方向可选双向、QQ → 短信、短信 → QQ、完全独立。长期记忆可选共享角色记忆、短信独立记忆、关闭。全局默认可以被单个联系人覆盖。

共享模式按方向读取角色原有的日记、结构化或向量记忆；短信摘要独立保存来源信息，允许写回时由 QQ 请求按需参考，避免把同一段短信反复复制进原记忆。方向关闭或切到独立模式后，之后的请求不再读取相应的跨渠道材料。已经在往次聊天中说出的事实不会被自动抹除。

短信记忆支持手动添加、编辑、删除、总结全部未整理消息或指定日期范围。自动总结默认关闭，开启后按新增消息数量触发，调用一次额外 API。切换模式不删除已有记忆。清空聊天与删除长期记忆分别操作。

## 陌生人与关系

「遇见陌生人」可以主动指定相遇情境；每次生成一个固定人设和固定号码，后续延续同一人物。陌生人只接触公开身份及自己的短信材料，不读取其他角色的聊天。

熟悉后可询问 QQ 联系方式；人物提出交换后，用户确认才加入主聊天。号码、短信、人物和记忆关系继续沿用，不创建另一个短信身份。

QQ 与短信独立管理黑名单。QQ 拉黑不会自动阻止短信；短信来信也不会自动解除 QQ 拉黑。用户可以阻止短信来信；角色也可以拒收后续信息，界面不会直接向发送方揭露对方的阻止操作。

## 延迟、主动来信与恢复

人物可以回复、安排稍后回复、忽略或拒收。延迟回复一次生成后保存在本地，到时投递，不反复调用模型等待。角色主动来信和随机陌生来信默认关闭；开启后遵循间隔、每天上限和安静时段，重新打开不会补做积压的模型调用。

网页关闭或后台暂停时不能保证计时持续运行，下次打开继续处理本地任务。未读角标、免打扰、草稿和待发照片均分别保存。

停止或失败保留待回复消息；晚到的旧请求不能覆盖新请求。意外关闭后遇到未完成状态，可在联系人详情选择「恢复未完成的请求」。重生成在成功前保留原回复，旧版本仍保存在数据中。

## 开关与备份

总开关默认关闭。关闭时不追加短信能力提示词、号码资料或短信专属上下文，不启动新的短信模型任务；保留所有数据。已有正常聊天记录和人物长期记忆继续按原设置工作。

完整备份、流式/分片备份和高级分类导出包含信息数据；高级分类名为「信息与短信」。信息设置中也有独立备份导入导出，按记录 ID 合并。迁移角色本身与原有 QQ 记忆时请使用包含「聊天与消息」的完整备份。

## 本地验证

安装开发依赖后可运行 `npm run test:sms`，使用真实 Dexie 与隔离的 IndexedDB 实现验证数据和事务。`node scripts/local-sms-preview.js` 提供独立演示页，使用演示人物、本地 IndexedDB 和模拟回复，不读取真实聊天、不请求真实模型。

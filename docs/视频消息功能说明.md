# 聊天视频消息

首期支持 Google Gemini 原生视频理解。入口为聊天拓展栏的「发送视频」，配置入口为设置页「视频理解」。

## 使用

1. 填写独立的视频 API 地址、密钥和模型，保存配置。模型可以手写，也可以拉取、搜索后选择；不会使用聊天模型兜底，不会自动替用户选模型。
2. 在普通聊天中选择本地 MP4 / WebM 或填写 HTTPS 视频文件直链。发送本地文件前显示封面、时长、大小和自定义播放器。
3. 视频以卡片形式进入当前聊天。点击现有回复入口时，先解析上下文里尚未解析的视频，再由原聊天模型按角色人设回复；也可以在卡片中单独完成解析。
4. 已有结果会缓存。卡片可查看、停止、重试，或填写 `00:10–00:30` 重新查看片段；片段观察单独保留，避免覆盖整段结果。

## 解析方式

- **画面与声音**：使用 Google 原生视频输入。小文件内联，超过 8 MiB 使用浏览器直接 Files 上传，并等待文件进入 ACTIVE。
- **仅画面**：浏览器提取最多 48 张带时间位置的画面，只向接口发送 JPEG 和时间位置，不发送音轨。快速动作可能遗漏。
- URL 优先由 Google 抓取。遇到抓取/格式类错误，来源允许跨域读取时，浏览器下载后走本地流程；鉴权、额度等错误不会触发额外下载重试。
- 本地文件上限 50 MiB、5 分钟。URL 直接抓取另受 Google 的文件、账号和模型限制；不能声称所有直链都可用。

## 数据与兼容

新增 Dexie 第 65 版 `videoAttachments` 表。文件以可序列化的 Data URL 单独保存，聊天只保存媒体引用和解析文本，不把视频原始字节塞入角色上下文。完整备份、高级「聊天与消息」备份、单聊 JSON 备份均包含视频文件；单聊导入时重新编号媒体引用。

删除视频消息或聊天后，清理没有任何聊天引用的媒体。普通聊天保存和解析状态更新不会反复扫描全部历史。切换聊天、删除消息或取消后，旧解析请求不会重新写回已经失效的消息。

视频配置保留在独立的 `apiConfig.videoUnderstanding` 中，切换聊天 API 预设不会清掉它。未来平台可在 `ChatVideo.providers` 中增加适配，复用消息卡片、存储和上下文处理。

## 本次验证

- 真实 Google 调用：使用新模块解析 13 秒公网 MP4，返回带时间位置的画面、声音与水印观察；首次 503 正确显示失败，手动重试后成功。测试凭据随后从独立预览配置中移除，没有写入项目文件。
- 真实浏览器、本地视频：预览、播放器、50 MiB 限制、发送卡片、模型必填、模型搜索选择、缓存状态已检查。
- 390px 独立响应式预览：发送窗口、仅画面流程和角色上下文衔接通过。界面测试使用独立数据与模拟模型；不代表真机 Safari 或 Android PWA 已验收。
- Node 回归覆盖独立配置、单聊/群聊上下文、失败/截断、文件上传、取消、重复请求、分页、备份恢复、片段补充与按需媒体清理。
- 完整应用资源及加载顺序已检查；首次登录受应用原有登录页控制，没有绕过登录。新增脚本位于数据库脚本之后。
